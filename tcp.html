02 · 核心概念

擁塞窗口 CWND = 網路傳輸的數學節流閥

時間離散化假設：以 RTT 為步長，CWND 演進即為離散數列

兩大核心數列階段
階段一：慢啟動（Slow Start）
CWNDn+1 = CWNDn × 2
等比數列，公比 r = 2，指數級增長
階段二：擁塞避免（Congestion Avoidance）
CWNDn+1 = CWNDn + d
等差數列，公差 d = 1，線性增長
切換條件
當 CWND ≥ ssthresh 時，從等比數列切換為等差數列
當 CWND ≥ Loss 時，觸發擁塞懲罰機制
核心符號說明
符號 意義 單位
n 傳輸輪次（RTT 步長） 次
CWNDn 第 n 輪擁塞窗口大小 MSS
ssthreshn 慢啟動邊界閾值 MSS
Loss 實體鏈路天花板 MSS
p 隨機丟包率 %
∑CWND 總吞吐量（級數和） MSS
四大基本假設
  • 時間離散化：以 RTT 為基本步長
  • 單一瓶頸鏈路：固定天花板 Loss
  • 隨機環境干擾：引入丟包率 p
  • 即時確認假設：每輪 ACK 即時回傳
03 · 演算法分類

從等差/等比到三次函數：四大演算法的數學進化

T
TCP Tahoe
1988 · 第一代
分段線性
等比 + 等差
擁塞反應：CWND 斷崖式重置回 1，ssthresh = Loss/2
⚠ 缺陷：斷崖式懲罰，恢復期極長
R
TCP Reno
1990 · 快速恢復
分段線性
快速恢復機制

05 · CUBIC 模型

TCP CUBIC：用三次函數的拐點征服高速網路

CUBIC 核心公式
CWND(t) = C · (t − K)³ + Wmax
C 縮放常數（= 0.4）
K 拐點時間（距上次擁塞的時間）
Wmax 上次擁塞前的歷史最大窗口值
t < K（拐點前）
上凹形態
斜率趨近 0，安全試探，避免擁塞
t > K（拐點後）
下凹形態
斜率急遽上升，多項式爆炸增長
與 Reno 的本質差異
在高速網路（高 BDP 環境）下，CUBIC 的三次函數恢復速度遠超 Reno 的等差線性模型。Linux 核心自 2.6.19 版起，將 CUBIC 設為預設演算法。

09 · 應用與討論

數學模型的工程應用：Linux 伺服器 TCP 調優實戰

問題場景：高延遲跨國鏈路
  • 跨國光纖/衛星鏈路：RTT 長，BDP（頻寬延遲積）極大
  • TCP Reno 等差遞增（d=1）：丟包後乘性減半，恢復極慢
  • 頻寬資源嚴重浪費，傳輸效率低下
解決方案：切換為 Google BBR
# 修改 Linux 核心參數 /etc/sysctl.conf
net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr
CWND 不再受離散丟包干擾，以 CWND = BtlBw × RTprop 恆定運行，徹底解放硬體實體帶寬
多流共存的博弈困境
BBR（不退讓）vs CUBIC（乘性減半）→ 資源不對稱分配
強者愈強、弱者愈弱的數學傾斜問題
BBR vs CUBIC 在不同丟包率下的吞吐量
圖示：BBR 在高丟包率環境下吞吐量維持穩定，而 CUBIC 因丟包懲罰機制導致吞吐量急劇下降。（來源：CS244 2017 BBR 研究）
10 · 未來展望

博弈論 × 數列模型 → 帕累托最優網路

引入「環境自適應禮讓因子」θₙ，解決 BBR 資源掠奪問題

改進公式：禮讓因子 θₙ
θₙ = (RTTbuffered − RTprop) / RTTbuffered
CWNDn+1 = CWNDn + d · (1 − θₙ)
機制說明
  • 網路積壓增加 → RTT 上升 → θₙ 趨近 1
  • 增長公差自動壓低，甚至變為負值（主動減速）
  • 不再盲目追求自己的「級數和最大化」
  • 將其他使用者的網路狀態納入計算
目標：帕累托最優（Pareto Optimality）
在實體頻寬有限的條件下，所有資料流經過動態互相禮讓後，達到「每條線都分到最合理的網速，且沒有任何頻寬被浪費」的最高效率雙贏平衡點。
